# libGDX UI Harness 1.4.0

## Highlights

- adds schema version 2 to the existing `ui_keyboard_gesture` tool with a 256-step hard bound while preserving version 1's exact 64-step contract;
- keeps one preflighted gesture request under one session/coordinator lease through the complete timeline and retains reverse press-order cleanup on every exit;
- adds read-only `ui_runtime_observe` for one explicit registered entity/property/correlation token without requiring an Actor, locator, or markup binding;
- adds read-only `ui_artifact_read` for session-owned opaque receipt retrieval in bounded 65,536-byte base64 chunks without exposing filesystem paths; and
- expands the catalog from 24 to 26 tools and advertises additive `ui_keyboard_gesture_v2` and conditional `ui_runtime_observe` capabilities.

## Compatibility and limits

Keyboard gesture version 1 retains its tool name, wire behavior, public constants, and 2..64-step limit. Version 2 accepts 2..256 steps. Both versions retain keycodes 0..255, at most 16 simultaneously held keys, individual and cumulative frame/tick wait bounds of 10,000, complete preflight before dispatch, one request-scoped lease, and an empty final held-key set. Results retain the originating schema's evidence bound under the existing encoded-response limit.

`ui_runtime_compare` remains unchanged. `ui_runtime_observe` uses the existing optional correlated runtime SPI and returns only bounded typed AVAILABLE or UNAVAILABLE evidence. It cannot enumerate runtime entities, traverse objects, access Actor/Stage state, reflect, infer, or mutate.

Existing artifact publication APIs and Publisher-only server construction remain source-compatible. Artifact retrieval is optional and requires an application-installed Reader tied to the same store. Reads require session ID plus an opaque receipt, enforce ownership/expiry/quota/integrity, and provide no path, URI, list, glob, delete, or arbitrary-read input.

No cross-request keyboard lease, persistent input transaction, runtime enumeration, or unbounded artifact download is introduced. Existing applications may adopt each additive capability independently.
