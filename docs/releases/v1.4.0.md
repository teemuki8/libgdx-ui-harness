# libGDX UI Harness 1.4.0 draft

## Highlights

- adds schema version 2 to the existing `ui_keyboard_gesture` tool with a 256-step hard bound;
- preserves schema version 1 validation, encoding, constants, and its 64-step hard bound;
- keeps one preflighted request under one session/coordinator lease through the complete timeline;
- retains reverse press-order cleanup after cancellation, deadline, callback, tick, frame-source, or
  session failure; and
- advertises additive capability `ui_keyboard_gesture_v2` while keeping
  `ui_keyboard_gesture_ticks` as the separate exact-tick capability.

## Compatibility and limits

This additive change keeps the tool name and version-1 wire behavior unchanged. Version 1 accepts
2 through 64 steps; version 2 accepts 2 through 256. Both versions retain keycodes 0 through 255,
16 simultaneously held keys, individual and cumulative frame/tick wait bounds of 10,000, complete
preflight before dispatch, and an empty final held-key set. Terminal results retain their
originating schema's 64- or 256-entry evidence bound under the existing MCP encoded-response limit.

No cross-request lease or session transaction is introduced. Long deterministic timelines use one
version-2 request; requests above 256 steps remain invalid.
