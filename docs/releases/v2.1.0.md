# libGDX UI Harness 2.1.0

This release adds bounded combined keyboard and relative-pointer input through the production
libGDX InputProcessor, and corrects Scene2D obscuration diagnostics for layered layouts.

## Combined input

The new `ui_input_gesture` tool accepts one versioned timeline of key presses/releases,
relative mouse movement, mouse button presses/releases, frame waits, and exact tick waits.
It preflights the entire request before dispatch, limits timelines to 256 steps, holds one
request-scoped tick lease, and releases harness-owned controls after cancellation or failure.
Deadline scheduler rejection terminates with explicit failure; cancellation cannot admit an
exact-tick operation after the request has already terminated.

Applications opt in by installing an application-owned relative-pointer adapter and combined
input coordinator. The adapter dispatches through the same production `mouseMoved` path used
by physical captured input. No global `Gdx.input` replacement or alternate camera command is
installed. Sessions advertise the capability only when its coordinator is installed. The MCP
catalog now contains 27 tools; existing `ui_keyboard_gesture` schema v1 and v2 contracts remain.
See [ADR 0040](../adr/0040-combined-input-gesture.md) for the integration and boundedness contract.

## Layered layout diagnostics

`OBSCURED` follows depth-first child drawing order rather than comparing sibling-local z
indices across unrelated branches. The Scene2D adapter derives `scene2d.layoutOnly=true` for
exact builtin Group, WidgetGroup, and backgroundless Table instances. Noninteractive layout
containers do not become false visual occluders; background-bearing, interactive, and custom
drawing actors remain candidates. Descendants are still examined, and genuine overlap checks
remain enabled. See [ADR 0041](../adr/0041-scene2d-obscuration-order.md) for conservative limits,
including the reserved property's existing 256-property bound.

## Compatibility and coordinates

Align these six `io.github.teemuki8` artifacts on **2.1.0**:
`harness-core`, `harness-scene2d`, `harness-lwjgl3`, `harness-protocol`, `harness-mcp`, and
`harness-agent-runtime`. Fixtures and benchmarks remain unpublished. Java 25 remains required.
Existing public constructors are retained; the new pointer capability is opt-in. Snapshot
consumers should expect the derived container property and corrected obscuration findings.
No visual approval or broader platform qualification is implied by this library release.

## Qualification

The complete isolated software-X11 `clean check javadoc` gate passed 1,054 tests with one
platform-conditional ACL skip. Native production-input fixtures and real MCP requests cover
combined movement, aim, fire, and exact ticks. A consumer recapture confirmed zero layout
findings across its title, playing, won, reset, and dead states without altering prior receipts.

Release preparation additionally checks binary/source compatibility against all six published
2.0.2 JARs, minimum/current ecosystem profiles, workflow invariants, and isolated local Maven
publication. The signed-tag workflow repeats release gates, validates the signed six-module
bundle, and publishes only after Central staging validation succeeds. Publication completion
