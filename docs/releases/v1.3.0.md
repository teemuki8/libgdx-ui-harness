# libGDX UI Harness 1.3.0

## Highlights

- adds `ui_keyboard_gesture`, a bounded atomic keyboard timeline that dispatches real Scene2D
  key input and holds harness-owned keys across completed frames;
- adds optional exact controlled-tick waits through the `ui_keyboard_gesture_ticks` capability,
  with fixed-delta, execution-epoch, runtime-frame, and UI-frame evidence;
- keeps gesture execution session-scoped, lazy, deadline-bounded, and render-thread confined;
- guarantees reverse-order key cleanup after cancellation, timeout, session shutdown, frame-source
  failure, tick failure, or input-dispatch failure;
- returns immutable version-1 terminal evidence with distinct failure categories, per-step frame and
  revision identities, held-key state, cleanup attempts, elapsed time, and trace correlation; and
- records the gesture lifecycle in bounded traces while keeping Scene2D and backend types outside
  the semantic and protocol models.

## Compatibility and limits

The release is source- and binary-compatible with 1.2.1. Existing sessions and clients continue to
work without enabling keyboard gestures. A session advertises `ui_keyboard_gesture` only when a
gesture coordinator is installed, and advertises `ui_keyboard_gesture_ticks` only when exact
controlled-tick support is also installed.

Gesture schema version 1 accepts 2 through 64 steps, keycodes 0 through 255, at most 16
simultaneously held keys, and frame or tick waits from 1 through 10,000. Every structurally valid
request must release all keys it presses. Actions use libGDX input dispatch and never invoke UI
listeners directly.
