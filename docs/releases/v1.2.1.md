# libGDX UI Harness 1.2.1

## Highlights

- replaces real-model evidence as a Maven publication condition with deterministic source, API,
  native fixture, parity-contract, treatment-preflight, and synthetic-pipeline gates;
- keeps real-model Agentic Palisade runs as manual or scheduled empirical qualification, so model
  availability and revision drift cannot block reproducible library releases;
- qualifies the unpublished markup fixture with
  `io.github.teemuki8:libgdx-ui-markup:0.4.1`, including an authoritative domain-state comparison
  that deliberately proves displayed/runtime `MISMATCH` evidence;
- qualifies the published `harness-agent-runtime` adapter at its agent-runtime 1.0.0 compatibility
  floor and the current agent-runtime 2.0.0 integration in separate exact locked profiles;
- makes both Agentic Palisade arms use the same markup-only XML/CSS construction path, with
  `HarnessSemanticSink` injection as the treatment difference; and
- seals the markup coordinate, combined identity digest, and XML/CSS resource digests in the
  offline treatment preflight.

## Dependency direction

The six published harness modules remain independent of libgdx-ui-markup. Markup is consumed by
the unpublished fixture and agentic workflow template, preventing a dependency cycle while making
markup semantics authoritative wherever the repository constructs new UI.

The `harness-agent-runtime` published POM continues to depend on agent-runtime 1.0.0. The 2.0.0
lane is an executable compatibility qualification, not a raised consumer floor.
