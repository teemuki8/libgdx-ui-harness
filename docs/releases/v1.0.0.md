# libGDX UI Harness 1.0.0 release candidate

Date: 2026-07-28

This candidate publishes the semantic Scene2D harness as five Java 25 modules: `harness-core`, `harness-scene2d`, `harness-lwjgl3`, `harness-protocol`, and `harness-mcp`. Fixtures and benchmarks remain repository-only. The candidate is not a published release until the signed-tag workflow validates and publishes its Maven Central staging deployment.

## User-visible capabilities

- Immutable bounded Scene2D semantics and metadata without custom Actor subclasses.
- Strict lazy locators, monotonic auto-waits, and faithful click, hover, focus, fill, key, scroll, drag, and pointer actions.
- Completed-frame bounded LWJGL3 screenshots.
- Versioned byte-bounded protocol, exact nine-tool MCP schema, opaque artifacts, causal traces, and safe replay.
- Real five-workflow reference qualification and a strict 400-observation Playwright parity verdict.

See `docs/guides/getting-started.md`, `docs/guides/agent-tools.md`, and `docs/guides/semantic-metadata.md` for installation, lifecycle, limits, safe artifact handling, metadata, and V1 non-goals.

## Security and release controls

Dependencies have fixed versions, committed lockfiles for every project and the API tool, SHA-256 verification metadata, and a clean offline gate. CI runs Linux/Windows/macOS checks, Linux Xvfb native and parity smoke, Windows/macOS native-adapter and fixture compilation, dependency review, lock drift detection, CodeQL, conditional released-API comparison, and failed trace/screenshot retention. Workflows grant read-only contents by default and only CodeQL receives `security-events: write`.

GitHub-hosted Windows and macOS runners do not expose usable WGL or NSGL
contexts. Those jobs therefore run every backend-neutral check and compile both
the LWJGL3 adapter tests and reference fixture; they do not misreport unavailable
headless graphics contexts as product failures. Linux Xvfb provides the real
hosted native runtime qualification: five fresh processes exercise MCP input,
semantic wait/query, framebuffer screenshot capture, trace recording and
replay, clean application exit, and temporary-resource deletion.

The golden screenshot uses bounded aggregate pixel tolerances for renderer
rounding and antialiasing differences. All five captures on one runner must
remain pixel-identical, preserving the fixed-step repeatability contract.

## Compatibility note

Java 25 is the V1 runtime and bytecode baseline. V1 does not claim Android, iOS, GWT/HTML, RoboVM, non-Scene2D rendering, OS-level automation, computer vision, arbitrary remote execution/filesystem access, a trace viewer, or accessibility certification.
