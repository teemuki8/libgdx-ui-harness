# libGDX UI Harness 1.0.0 release candidate

Date: 2026-07-28

This candidate publishes the semantic Scene2D harness as five Java 25 modules: `harness-core`, `harness-scene2d`, `harness-lwjgl3`, `harness-protocol`, and `harness-mcp`. Fixtures and benchmarks remain repository-only. The candidate is not a published release until the signed-tag workflow validates and publishes its Maven Central staging deployment.

## User-visible capabilities

- Immutable bounded Scene2D semantics and metadata without custom Actor subclasses.
- Strict lazy locators, monotonic auto-waits, and faithful click, hover, focus, fill, key, scroll, drag, and pointer actions.
- Completed-frame bounded LWJGL3 screenshots.
- Versioned byte-bounded protocol, exact nine-tool MCP schema, opaque artifacts, causal traces, and safe replay.
- Real five-workflow reference qualification and a strict 400-observation Playwright parity verdict.

See `docs/guides/getting-started.md`, `docs/guides/agent-tools.md`, and `docs/guides/semantic-metadata.md` for installation, lifecycle, limits, safe artifact handling, metadata, and V1 non-goals.

## Security and release controls

Dependencies have fixed versions, committed lockfiles for every project and the API tool, SHA-256 verification metadata, and a clean offline gate. CI runs Linux/Windows/macOS checks, Linux Xvfb parity smoke, real Linux/macOS native smoke qualification, Windows native-adapter and fixture compilation, dependency review, lock drift detection, CodeQL, conditional released-API comparison, and failed trace/screenshot retention. Workflows grant read-only contents by default and only CodeQL receives `security-events: write`.

On macOS, the matrix check excludes `:harness-lwjgl3:test` and
`:harness-fixtures:test`: Gradle test workers are helper threads and cannot own
Cocoa's required first thread. The immediately following native qualification
replaces the fixture task with `ReferenceApplicationSmokeTest`, whose real
LWJGL3 JVM is launched with `-XstartOnFirstThread`. Five fresh processes
exercise MCP input, semantic wait/query, framebuffer screenshot capture, trace
recording and replay, clean application exit, and temporary-resource deletion.
The golden screenshot permits only a one-level RGBA rounding difference across
renderers; all five captures on one runner must remain pixel-identical.

GitHub-hosted Windows runners do not expose a usable OpenGL driver. Windows
therefore runs every backend-neutral check and compiles both the LWJGL3 adapter
tests and reference fixture; it does not misreport an unavailable WGL runtime
as product failure. Linux Xvfb and the macOS Cocoa subprocess provide the real
native runtime coverage.

## One-time Maven Central onboarding

The `maven-central` GitHub environment exists, but publication remains disabled
until the repository owner completes Central Portal identity verification:

1. Sign in to <https://central.sonatype.com/> with the `teemuki8` GitHub account.
2. Register `io.github.teemuki8` under **Namespaces**. If Central requests proof,
   create the exact temporary public GitHub repository name supplied by the
   portal, complete verification, then delete that repository.
3. Generate a Central Portal user token. Store its generated username and
   password as `MAVEN_CENTRAL_USERNAME` and `MAVEN_CENTRAL_PASSWORD` in the
   repository's `maven-central` environment; a GitHub token cannot replace it.
4. Add the signing secrets described below. Do not create or push a release tag
   until all six environment values are configured.

Before publishing from the protected `maven-central` GitHub environment, a
repository administrator must configure environment secret
`RELEASE_SIGNING_PUBLIC_KEY`
with the armored public key of the authorized tag signer and environment
variable `RELEASE_SIGNING_FINGERPRINT` with that key's exact 40- or 64-hex
primary fingerprint. Configure `MAVEN_CENTRAL_USERNAME`,
`MAVEN_CENTRAL_PASSWORD`, `MAVEN_SIGNING_KEY`, and
`MAVEN_SIGNING_PASSWORD` as environment secrets. Rotate the public key and
fingerprint together after independent fingerprint verification. The workflow
imports only that configured public key into an isolated temporary GnuPG home,
requires exactly one primary key and an exact normalized fingerprint match,
then deletes the GnuPG home. Publication secrets are step-scoped and are never
inherited by checkout, setup, apt, or artifact-upload actions.

Release accepts only an annotated PGP-signed semantic-version tag that resolves to the workflow commit. It requires Maven Central user-token credentials and an in-memory PGP private key/password, creates a deterministic five-module signed bundle, rejects missing artifacts/signatures and unpublished modules, uploads as `USER_MANAGED`, waits for Central `VALIDATED`, then publishes and waits for `PUBLISHED`. Central authorization is written only to a mode-0600 temporary curl config that every exit path deletes; it never appears in curl arguments, logs, or diagnostic artifacts.

## Compatibility note

Java 25 is the V1 runtime and bytecode baseline. V1 does not claim Android, iOS, GWT/HTML, RoboVM, non-Scene2D rendering, OS-level automation, computer vision, arbitrary remote execution/filesystem access, a trace viewer, or accessibility certification.
