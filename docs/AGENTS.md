# Documentation Instructions

These rules apply to files under `docs/`.

- Specifications describe observable behavior and constraints, not implementation guesses.
- Plans use exact paths, symbols, dependencies, test-first steps, acceptance criteria, and verification commands.
- Decisions that alter public APIs, protocol compatibility, threading, timing, or security require an ADR.
- Use absolute dates and version numbers where reproducibility matters.
- Do not use `TBD`, `TODO`, placeholders, or unmeasurable claims such as “fast,” “robust,” or “easy.”
- Distinguish committed V1 scope from later possibilities.
- Link primary sources for external constraints.
- Keep diagrams synchronized with the text and module names.
- After editing, scan for contradictions, unresolved placeholders, and acceptance criteria without proof methods.
